# Contributing to Delfini

Thanks for your interest in contributing! This repo follows a conventional open-source flow:

1. **Open an issue first** for anything non-trivial — bug reports, feature proposals, behaviour
   questions. Small typo/doc fixes can go straight to a PR.
2. **Fork the repo and create a branch** from `main`.
3. **Make your change**, with tests where behaviour changes.
4. **Open a pull request** against `main`. Describe what changed and why; link the issue.
5. **Review** — a maintainer reviews, may request changes, and merges when green.

## Development setup

Requirements: Node.js 20+ and [pnpm](https://pnpm.io/) 10+ (`npm install -g pnpm`).

```bash
pnpm install

# Build in dependency order
pnpm --filter @delfini/drift-engine build
pnpm --filter @delfini/action-core build
pnpm --filter @delfini/cli build
pnpm --filter @delfini/action build

# Verify before pushing
pnpm typecheck
pnpm lint
pnpm test
```

## Add a changeset to your PR

This repo versions and publishes its npm packages (`@delfini/cli`, `@delfini/drift-engine`,
`@delfini/action-core`) with [changesets](https://github.com/changesets/changesets). Any PR that
touches `packages/cli/**`, `packages/drift-engine/**`, or `packages/action-core/**` must include
a changeset (CI enforces this):

```bash
pnpm changeset
```

Pick the affected package(s), choose the semver bump, and write a short user-facing summary —
prefix it with an impact marker (`[cli]`, `[drift-engine]`, `[skill]`, `[action-core]`) so the
generated CHANGELOG carries the right surface tag. For a change that genuinely needs no release
(e.g. test-only), use `pnpm changeset --empty`. Full details in
[`.changeset/README.md`](./.changeset/README.md).

Do **not** edit `CHANGELOG.md` files or package versions by hand — both are generated by
changesets on release.

## Things to know before changing the analysis core

- **`packages/drift-engine` is pure logic** — no I/O, no LLM client, no credentials, no `fetch`,
  no `process.env`. Its only runtime deps are `zod` and `picomatch`. Lint enforces this; adding
  any other dependency is a regression.
- **`packages/cli` never calls an LLM** — it is deterministic plumbing (git, file I/O, prompt
  assembly, validation, report rendering). LLM dispatch happens in the host coding agent.
- **Three release gates are required-green** on every PR touching the published packages:
  the drift-engine prompt-snapshot parity test (gate A), the Lite action + action-core suites
  (gate B-lite), and the bundled-CLI parity test (gate C). Do not skip or weaken them; if the
  prompt snapshot fires, see `packages/drift-engine/README.md` for the deliberate-re-snapshot
  procedure.
- **Code style** is enforced by Prettier (`.prettierrc`) and ESLint (`eslint.config.js`):
  named exports only, no manual version edits, kebab-case file names.
